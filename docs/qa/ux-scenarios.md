# UX-scenario catalog — Builder Pro AI

**synced @ ac581d4**

This is the single, maintained source of truth for every user-facing scenario in the webview
(React 19 + TypeScript over the Tauri host). It supersedes the frozen Russian first-session catalog
(`docs/qa/ux-first-session-scenarios.md`) and its investigation report
(`docs/qa/ux-investigation-report.md`) — their findings/suspects are folded in here, re-structured to
the columns below and expanded from first-session-only to full coverage. Every change that
adds/changes/removes a user-facing control, view, state, or a wire verb the UI consumes MUST update
the affected rows here and bump the `synced @` header (see `CONTRIBUTING.md` → "UX scenarios"). The
testing loop (`docs/qa/ux-test-results.md`) audits the code against every row here.

**Columns.** ID = `<EPIC>-NN` (stable, append-only, never renumber). Entry = where it starts.
Steps = the user actions. Expected = result + exactly what the user should SEE. States = which of
worked / failed / empty / loading / disabled apply and what each renders. Errors/edge = the error +
how it is surfaced (toast / inline / banner) and edge cases. Checks = what a code-auditor verifies
(control exists, handler fires, ipc called, state rendered, error handled, no dead end).

**Conventions.** Errors from the orchestrator daemon are mapped by `describeOrchdError`
(`src/ipc/orchd.ts`): Invariant → "invalid operation: {msg}", Conflict → "conflict: {msg}",
NotFound → "not found", Validation → "invalid data: {msg}", Io → "service error: {msg}", Consent →
"connection consent required: {msg}", Policy → "blocked by policy: {msg}", disconnected /
incompatibleOrchd → "orchestrator unavailable". Toasts are a FIFO queue (append, cap 5 drop-oldest,
auto-dismiss 4000 ms, manual "×"). Mutating dialogs use the shared `useSubmitGuard` (ref-based
synchronous double-submit lock). All user-facing copy lives in `src/strings.ts`.

**Epics.** ON first-run/onboarding · DA daemon lifecycle · WS workspaces · TE terminals · FI files ·
PR projects (incl. Rules tab) · GO goals + metric_refs · ID ideas · RE research · IN insights ·
TA tasks · GR graph · EX extensions · DG degradation (orchd-down gating, reconnect, toasts, honest
empty/loading/failed) · XC cross-cutting.
